Multiplication occurs in several forms:

  1. Regular multiplication (all variables unknown)
  2. Known result (integer factorization)
  3. Multiplication by a known constant value
  4. Squaring (** 2)
  5. Power-of-two modular multiplication and squaring ({*} and {**} 2)

The best optimization for multiplication is to avoid it altogether. When only an approximate value or an upper bound is needed and exact precision is unnecessary, adding integer binary logarithms (+: (|: a) = aLog;) is significantly faster.

Approximate Value

In practical engineering problems where exact precision is not required, you can reduce large numbers using right bit shifts before multiplying, and shift the result back afterward: 

// approximate multiplication
// a * b = r 

a >> 3 = ta 
b >> 3 = tb

ta * tb = tr 

tr << 6 = r

Setting an Upper Bound

During compilation, the upper bounds of the multiplicands are checked first to select the most efficient multiplication algorithm. Setting tight upper bounds significantly reduces the number of generated clauses.

It is preferable to use exact powers of two as upper bounds so that higher-order bits are simply fixed to false. Using a non-power-of-two upper bound requires generating extra comparison clauses.

Valid upper bounds (known constants): 

a * b = r

a < 16 // upper bound must be a known value
b < 2 ** 4 // for simplicity, exponentiation can be used

Invalid upper bounds (variable expressions): 

a * b = r

// These are not upper bounds, as these values are not known values.
a < t + 8
b < a

Squaring

Because both operands are identical, squaring (a ** 2 = r) is significantly faster and generates far fewer clauses than general multiplication. Moreover, when multiplying large numbers via Karatsuba's algorithm—which decomposes multiplication into smaller sub-multiplications—squaring ensures that many of the resulting sub-operations are also squarings. Currently, a * a = r is automatically transformed into a ** 2 = r. 

// 1108 clauses                   
a * b = r 

a < 2 ** 10
b < 2 ** 10

size 20 0

// 599 clauses    
a ** 2 = r 

size 20 0
