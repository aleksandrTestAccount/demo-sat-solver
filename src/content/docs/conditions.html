The language supports three types of conditional statements: boolean conditions, implication-like conditions, and ternary conditions.

Boolean Conditions

Syntax: b1 ? b2 == b3 (costs 2 clauses). If b1 is true, then b2 must equal b3. If b1 is false, b2 and b3 may or may not be equal. Note that this is not a standard equation line.

Implication-Like Conditions

Syntax: boolean1 ? number1 = number2 (costs 2 clauses per bit). For example, in a ? x = v, if a is true, then x equals v; if a is false, the condition is ignored and x may or may not equal v.

  • Negation is allowed before the condition: !a ? x1 = x2.
  • Left-hand side and right-hand side positions cannot be swapped.
  • Because this is not a standard equation line, any nested operations must be enclosed in parentheses, or an error will occur: (a || b) ? (x1 + x2) = (x3 - x4).

Ternary Conditions

Syntax: r = b ? n1 : n2 or b ? n1 : n2 = r. Although this structure resembles traditional ternary operators in other languages, it translates under the hood into two separate implication-like conditions: 

a ? x1 : x2 = x3 /* 
    transforms into:
    a ? x1 = x3
    !a ? x2 = x3
*/

!a ? y1 : y2 = y3 /* 
    transforms into:         
    !a ? y1 = y3
    a ? y2 = y3
*/

Ternary Condition with Known Values: If both branches are known constant values, ternary conditions are completely free—only direct bit links are created. 

// this "convertion" boolean to number is free, only links will be created:   
// {n:0: a, n:1: false, n:2: false, n:3: false} 
a ? 1 : 0 = n; // or n = 1 ?* a

// this is also free
// {v:0: true, v:1: b, v:2: !b, v:3: false}
b ? 3 : 5 = v; 

size 3 0;

Important: Both ternary branches must be valid (satisfiable / SAT) regardless of whether the condition is true or false. If an inactive branch causes an overflow or unsatisfiable constraint, the entire system evaluates to false: 

// result is false

x > 1

r = false ? (200 * x) : 3
