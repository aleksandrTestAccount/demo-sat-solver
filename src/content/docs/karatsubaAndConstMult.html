Karatsuba Algorithm

The Karatsuba algorithm is implemented for standard multiplication (*) and squaring (** 2), but it is not implemented for power-of-two modular multiplication ({*}) or modular squaring ({**} 2).

For small numbers, simple table-based multiplication is used. Switching to the Karatsuba algorithm occurs at the following thresholds:

  • Squaring (** 2): Switches to Karatsuba when the operand size is 30 bits or more.
  • Regular multiplication (*): Can switch for numbers larger than 20 bits when upper bounds are known.
  • Unbounded multiplication: If no upper bound is set, the switch occurs at size 176 0.

Switching to Karatsuba for regular multiplication is more complex than for squaring because the language supports arbitrary factorizations (for example, a * b = 256 allows [16, 16], [2, 128], [1, 256], and so on). When no upper bound is specified, the initial step generates an overflow check instead of performing the first sub-multiplication, executing 2 multiplications instead of 3 (logged as full, bitSize in karatsubaLog). Because this overflow check is still costly, setting explicit upper bounds is recommended: if both operands have bit sizes smaller than half of the total bit size, no overflow checks are needed.

You can inspect the generated sub-multiplications in Result Details -> karatsubaLog: 

a ** 2 = r

size 70 0

config solve false

/* 
    Details -> karatsubaLog

    multiplier bit size, result bit size
    35,71  
    18,37
    17,35
    19,39

    3 squarings, with multipliers bit sizes 18, 17 and 19.
*/

Multiplication by a Known Value

Multiplication by a known constant differs from general multiplication because bit-shift grouping is used to minimize the number of additions. For example, multiplying by 27 requires only 2 additions: 

a * 27 = r  /* 
    transforms into
    a + (a << 1) = t
    t + (t << 3) = r
    a >= 0
*/

You can inspect how additions were grouped in Result Details -> multAdditions.

Note: The current grouping implementation for constant multiplication only uses additions for small numbers, is not yet optimal, and will be redesigned in future versions. In some cases, writing equations manually using shifts and subtraction is much more efficient—for example, multiplying by 31: 

// 31 * a = r 
a << 5 = t 
t - a = r

When using this subtraction trick, allocate one extra bit to prevent overflow during the intermediate shift (a * 32). Currently, two constant-multiplication grouping strategies are available via configuration: 

config multByConstMethod 1
config multByConstMethod 2
