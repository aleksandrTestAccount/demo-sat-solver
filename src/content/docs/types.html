The language supports only two data types: boolean and rational number. Data types are determined automatically by operators. For example, all variables in arithmetic equations (such as a + b = r) represent rational numbers, whereas all variables in boolean equations (such as x1 || x2 == x3) represent boolean values.

Boolean type

Booleans represent standard logical values: true and false. 

//a,b,c - boolean type vars
a == true
b == false
1 > 2 == c 
size 4 0
//result: {a: true, b: false, c: false}

c == true
1 > 2 == c 
size 4 0
//result: false

Rational number type

A rational number is stored as a fixed-size sequence (or vector) of boolean values in two's complement representation, with fixed precision for integer and fractional parts plus an additional bit reserved for the sign.

For instance, when defining size 4 3:

  • 4 bits are assigned to the integer part.
  • 3 bits are assigned to the fractional part.
  • 1 bit is dedicated to representing the sign (consuming 8 bits in total).

Known Value Usage: If an integer value exceeds the allocated integer bits, it causes an overflow error. Fractional values exceeding the designated fraction bits are rounded accordingly.

Direct Bit Access: Each bit of a rational number is a boolean and can be accessed by index using varName : bitIndex. For example, v:3 == true sets the third bit of variable v. The sign bit (the last bit) can be accessed via v:s == false, v:-1 == false, or by its explicit position (such as v:7 in an 8-bit number). Checking the sign bit prevents overflow conditions in addition and subtraction.

Unary negation (-) is omitted from the language because it requires performing addition after bitwise negation, which is not a free operation. Instead, use binary subtraction from zero: 0 - varName = negVarName.

Rational Number Representation

Numbers can be written in four formats: binary (0b), hexadecimal (0x), octal (0o), and decimal (0d). If numbers have a fractional part, it is better to use binary format to minimize approximation errors.

  • 0b101.1 equals decimal 5.5
  • 0xB.A equals decimal 11.625
  • 0o13.3 equals decimal 11.375
  • 0d12.34 equals decimal 12.34

Since leading zeros at the beginning of numbers can be interpreted differently across programming languages, an error is raised to avoid ambiguity. 

001 = x    // error
0b001 = x  // ok
05 = x     // error
0d05 = x   // ok
