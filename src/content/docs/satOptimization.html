Before solving the 3CNF-SAT problem, an optimization pass simplifies the generated clauses through four main steps:

  1. Known values removal: Known literals (0 or 1) are removed from clauses. If a clause contains 1, the entire clause evaluates to true and is discarded.
  2. Single-literal clause resolution: Clauses containing only one literal fix that literal's value to 1, and all occurrences of the variable in other clauses are updated accordingly.
  3. Pairs reduction: Simplifies two-literal clauses (pairs) that share the same variables with differing signs.
  4. Pure literal check: Identifies variables that appear exclusively as positive or exclusively as negative literals across the entire formula and assigns them fixed values (0 or 1).

Pairs Reduction

When two pairs with the exact same variables are discovered, three cases can occur:

1. Identical pairs: One duplicate pair is removed.

2. One matching literal, one opposing: The matching literal is fixed to 1, and both clauses are discarded. 

// in this case, result will be {x1: false} and both clauses are removed               
clauses {
    !x1 x2
    !x1 !x2
}

// in this case, result will be {x2: true} and both clauses are removed               
clauses {
    !x1 x2
    x1 x2
}

3. Both literals are opposite: Variable links are created equating the first literal of the first clause to the negation of the second literal, and both clauses are discarded. 

// in this case, links will be {x1: !x2} and both clauses are removed               
clauses {
    x1 x2
    !x1 !x2
}

// in this case, links will be {x1: x2} and both clauses are removed               
clauses {
    x1 !x2
    !x1 x2
}

Pure Variable Check

Variables that appear with only one polarity throughout the clause set are automatically resolved during optimization: 

// in this case, x1 is pure, result will be {x1: false}, 
// and all clauses will be removed during optimization step                
clauses {
    !x1 x2 x3
    !x1 !x2 !x3 
    !x1 x4 x5 
    !x1 !x4 !x5
}

During benchmarking or when comparing how many clauses and variables each equation produces, you can disable pure literal elimination with config checkPure false: 

// in this case, x1 is pure, but no optimization occurs.                
clauses {
    !x1 x2 x3
    !x1 !x2 !x3 
    !x1 x4 x5 
    !x1 !x4 !x5
}

config checkPure false

Optimizer Limitations

The optimizer does not currently perform certain higher-order resolutions—for example, reducing x1 x2 x3 and x1 x2 !x3 into a single clause x1 x2. Such cases arise rarely, and additional optimization passes may be added in future updates.
